DOM 和 BOM ​

  1. 什么是 DOM?

DOM (Document Object Model, 文档对象模型)

DOM 是浏览器把 HTML 文档解析出来的文档对象模型, 用来操作页面文档

  • DOM 的核心对象是 document, 它是整个页面文档的入口
  • DOM 将 HTML 文档抽象成树形结构 (DOM 树), 每一个标签, 文本, 注释都是树上的节点
  • JS 通过 DOM API 实现对页面的操作: 获取 / 修改元素, 修改内容, 修改样式, 增删节点, 绑定事件等
  • DOM 属于文档层面, 只和页面文档相关
js
// 获取页面元素
document.getElementById('app')

// 修改页面内容
element.innerHTML = 'hello'
  1. 什么是 BOM?

BOM (Browser Object Model, 浏览器对象模型)

BOM 是浏览器提供的浏览器对象模型, 用来操作浏览器窗口本身

  • BOM 的核心对象是 window 浏览器的全局对象, 所有全局变量都挂载在它上面
  • BOM 提供和页面文档无关的浏览器能力: 浏览器窗口, 地址栏, 历史记录, 定时器, 弹窗, 浏览器信息等
  • 常用 BOM 对象: location, history, navigator, screen, 定时器 setTimeout / setInterval
  • DOM 其实是 BOM 的一部分: window.document 就是 DOM 的入口
  1. 总结DOM 和 BOM 的区别是什么?

DOM 管页面内容, BOM 管浏览器窗口

Script 标签位置 ​

<script> 为什么建议放在 <body> 的底部?

浏览器解析 HTML 是从上到下串行解析的. 当解析遇到 <script> 时

  • 如果是外部脚本, 会暂停 HTML DOM 的解析, 去下载 JS 文件, 下载完成后还要执行 JS 代码
  • JS 执行时会阻塞 DOM 树构建, 因为 JavaScript 可以修改 DOM, 修改 CSSOM, 浏览器不能一边构建 DOM, 一边让 JS 修改它, 所以必须暂停解析

如果把 <script> 放在 <head> 里

  • HTML 还没解析到页面 DOM 元素, DOM 树不完整, JS 如果操作页面元素, 会获取不到元素, 报错
  • JS 的下载和执行会阻塞后续 HTML 解析, 页面白屏时间变长, 用户体验差

放在 </body> 之前 (Body 底部)

  • 此时 HTML 已经解析完毕, DOM 树构建完成, JS 可以正常访问页面上所有 DOM 节点
  • JS 的下载执行不会阻塞页面 HTML 的解析渲染, 减少白屏时间, 页面能更快展示内容

补充

现在不一定要放底部, 可以使用属性解决阻塞问题

  • 使用 defer 属性 <script defer src="...">: 脚本后台异步下载, 等到整个 HTML 解析完成之后, 再按顺序执行脚本. 不阻塞 DOM 解析
  • 使用 async 属性 <script async src="...">: 脚本后台异步下载, 下载完成立刻执行, 执行顺序不能保证, 适合不依赖 DOM, 不互相依赖的脚本

区别: defer 解析完再执行, 保序, 等价于放到 body 底部, async 下载完就执行, 顺序不可控
